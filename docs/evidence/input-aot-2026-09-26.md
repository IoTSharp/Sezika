# 修正输入路径的两 RID Native AOT 回归

本轮已完成 S3-10 修正输入路径的 `win-x64` / Ubuntu WSL2 `linux-x64` Native AOT 回归：256-token 前缀预算、1024-token 总长度、默认 strict 与显式 laya_compatible。使用原有本地固定权重、46 条真实上游参考和冻结容差。两 RID 的 SIMD/CUDA 各38回答+4非法拒绝通过，scalar各三条明确长输入通过；两个原生输入测试程序各138项检查通过。四次最终 AOT 发布均无编译/trim 警告；4条候选数量合同差异仍然保留，完整上游合同未通过。

[总索引](input-aot-2026-09-26/summary.json)包含六组矩阵、八项发布/测试/负向检查、88个源文件验证和316个逐字节归档文件的 SHA-256。[源文件快照](input-aot-2026-09-26/source-hashes.json)、[原生程序身份](input-aot-2026-09-26/native-binary-hashes.json)、[运行项目依赖图](input-aot-2026-09-26/runtime-dependencies.json)和[原始进程日志](input-aot-2026-09-26/processes/)均保留，可独立核对范围和退出语义。

## 原生执行门槛

`OracleCapture --require-aot` 在读取输入、加载模型和创建输出目录之前检查托管宿主以及两项动态代码能力。导出记录 RID、这三项观测、实际进程 SHA-256、PID、启动时间和 argv。`Sezika.Tests --prompt-contract-aot` 使用相同门槛，运行既有输入合同检查。

负向试运行发现：`PublishAot` 生成的中间托管 DLL 的 runtimeconfig 也设置 `System.Runtime.CompilerServices.RuntimeFeature.IsDynamicCodeSupported=false`，其两项动态代码能力均为 false。只检查能力开关会把 `dotnet xxx.dll` 误认成原生执行。因此增加 `AppContext.GetData("TRUSTED_PLATFORM_ASSEMBLIES")` 的托管宿主检测；Windows 与 Linux 的最终中间 DLL 均返回 exit 2，且未创建输出目录。原生可执行文件直接启动并通过门槛。初版门槛的试运行保留为诊断，不作为最终通过证据。

发布命令、原生文件格式、静态依赖与运行时能力共同组成证据。Windows 为 PE32+ x64，CLR directory RVA/size 均为零；Linux 为 x86-64 ELF PIE。原生导入仅包含系统库；CUDA Driver 在运行时显式加载，不会出现在静态依赖清单中。两个发布项目的 NuGet 图均不包含 ILGPU。

本轮计时用于预算与执行取证，存在并行工作，不是性能 benchmark。此次不覆盖 W8A32 长输入质量、裸机 Linux、近并列预测、无限长度 BPE 成本、完整真实模型取消/卸载矩阵或正式发布；语言质量与校准仍需独立验收，模型输出保持未校准语义。
