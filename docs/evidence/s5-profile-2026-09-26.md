`peak_owned_bytes` 的准确口径是 **最近一次 `ResetTelemetry` 以来的已追踪分配峰值**：该调用会重置峰值为当前 owned bytes，每行额外 instrumented 请求及最后短请求都会重置。矩阵记录到的最大 owned 峰值为 1,363,124,292 bytes；最后短请求再次重置后，卸载后快照中的峰值为 1,288,917,004 bytes。不能把任一快照标成整个 context 生命周期的最高值，也不能用重置后的低数值证明长输入峰值下降。Driver/context 额外内存不在 owned 账本内，free/total 则是整张设备的快照。

卸载后 **owned bytes、owned allocation count、loaded module count、release failure count 均为 0**，模型/encoder/head/pipeline/embedding 弱引用哨兵全部回收。预取消、首个 encoder trace 后取消、非法题型、取消后恢复及卸载后拒绝均通过。四-token 数值 smoke 最大误差为 encoder `1.2397766e-5`、logits `5.2154064e-7`、probability `1.6837372e-7`，分别小于原有冻结容差 `0.05` / `0.005` / `0.002`；这个短数值检查不代替独立的长序列 oracle 对照，也不表示语言质量或校准通过。

## 代码和构建

普通 .NET 执行的 `executable_sha256` 可能仅代表 dotnet host 或 apphost。本轮补充 `code_artifacts`，显式绑定进程文件以及输出目录中 `Sezika.Benchmarks.dll`、`Sezika.dll`、`Sezika.Cuda.dll` 三个固定程序集；不使用反射发现、`Assembly.Location` 或动态加载。Native AOT 继续用原生可执行文件标识实现。`request_token_budget`、`request_deadline_seconds` 直接来自真实 session 配置，便于解释合法长输入的超时失败。

实测结束后的源代码另行加固了 AOT 身份判定：要求没有托管宿主且动态代码 support/compiled 均为 false，防止关闭开关后由 dotnet 启动中间 DLL 被误报为 AOT；同时明确新报告的 CUDA 峰值重置区间和未完成请求标签。上述修改未覆盖或重新标记本页已测 DLL 和 JSON；这些运行本来就是 `native_aot=false`。实测对应的三个工具源文件已按原哈希保存在 [measured-source](s5-profile-2026-09-26/measured-source/)，后续源码位于独立的 [final-source](s5-profile-2026-09-26/final-source/)，不能把新构建哈希套到旧性能样本上。

在独立 `.artifacts/build/s5-profile-20260926` 输出目录构建，最终构建为 0 警告、0 错误；`--self-test` 通过。该自检只覆盖分位数、请求序列化及参数边界，不加载模型。构建/自检、token smoke 和矩阵均通过仓库 runner 保存根进程 PID、启动时间、参数、父链、退出码及清理记录。构建期限 180 秒，自检/预检外部期限 60 秒，预检内部期限 30 秒；版本与产物哈希见 [执行索引](s5-profile-2026-09-26/execution-index.json)。

之后两次隔离构建 `.artifacts/build/s5-profile-final-20260926` 和 `s5-profile-final2-20260926` 均为 0 警告、0 错误。前者包含 AOT 判定和资源口径修正；后者另含 partial pipeline 标签修正，最终 `--self-test` 通过。执行索引分别保存两次构建的产物身份、日志和最终源码，不覆盖性能采样版本。

final2 的两个真实**无模型负例**已通过，见 [AOT gate checks](s5-profile-2026-09-26/aot-gates-final/checks.json)。普通 dotnet 执行，以及 `dotnet exec --runtimeconfig` 显式关闭两个动态代码开关后的执行，都在读取模型前因 `--require-aot` 返回预期退出码 2：`native_aot=false`、`managed_host_detected=true`、`loads=[]`。第二个进程实际报告 `is_dynamic_code_supported=false`、`is_dynamic_code_compiled=false`，证明拒绝来自托管宿主识别而非配置未生效。外层 runner 退出 0，两次子进程的 exit 2 均作为预期拒绝保留，不伪装成普通成功退出。

每个负例上限 30 秒，外层整体上限 90 秒；原 runtimeconfig、独立关闭开关配置、检查脚本、两份失败报告及三组 runner 记录全部归档。两个子进程在 CIM 采集前已退出，`root_command_line_captured=false` 如实保留；已记录启动句柄 PID/时间、结构化完整参数、工作目录、直接父 PID 和 launcher 命令/父链，未伪造缺失的 CIM 原生命令行。这里验证的是拒绝语义和身份标记，没有加载权重、执行新性能测量或证明新的 Native AOT 原生运行。

final2 另执行了一个[真实模型取消观测检查](s5-profile-2026-09-26/partial-observation-check.json)，用于验证实际 pipeline 调用后仍能准确报告未完成状态：工具 20 秒取消期限、runner 40 秒，进程按预期退出 2，`decision_cancelled`；short-32 的 discovery 记录 19 次 pipeline 进入，完整响应为 null、正式样本为 0、成功行计数为 0，新标签为 `observed_pipeline_calls_request_incomplete`。本次检查与其他负载并行，只验证取消报告语义，耗时完全排除在性能统计之外；19 条记录不表示 19 次已完成输出。该报告绑定 final2 的真实产物 hash，未替换旧性能版本。

## 执行隔离与后续边界

画像输入和报告口径见 [S5-06 工具说明](../performance-profile-s5-06.md)。实际启动前，根代理确认其余模型验证结束并释放窗口；执行器再次核对五个已知 AOT/质量任务的 PID、启动时间和命令，确认对应进程已结束及 Linux supervisor 完成。检查记录分别保存在 [smoke 窗口](s5-profile-2026-09-26/cuda-smoke-window.json)和[矩阵窗口](s5-profile-2026-09-26/cuda-matrix-window.json)。这证明已知任务的协调状态，不声称整台机器没有其他系统或用户进程。CUDA 窗口内没有同时运行另一个本轮 CPU/GPU 模型任务。

本次已按 `short` / 1 问 / 1 正式样本 / 0 预热 / 1 生命周期先做极小验证，随后完成 CUDA 九行、每行 3 正式样本、1 预热、1 生命周期。全矩阵共 123 个题位，CUDA 每行含一次 discovery、一次 warmup、三次正式和一次 instrumented 请求，因此矩阵为 738 次逐题 forward，另有原有 cold、数值 smoke 与生命周期诊断。smoke 内部/外部期限为 150/180 秒，矩阵为 1700/1750 秒，均未达到超时期限。原始参数、准确版本、进程树和退出记录均保存在执行索引中。

SIMD 的 CPU split 会再增加每题一次独立 encoder/head pass。本次 CPU 矩阵在 CUDA 退出并归还窗口后执行，采用 1 样本、0 warmup 在同一有界进程尝试九行；已经保存 long-32 的真实 300 秒期限失败。后续优化仍需固定输入、数值和质量门槛，按行消融并保留失败；不能只由短请求性能宣布完整长输入矩阵达标。
